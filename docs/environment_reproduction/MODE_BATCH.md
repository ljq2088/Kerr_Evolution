# 共享度规的多通道求解

入口 `src/report_environment_mode_batch.py` 接收 `--scalar-ells`，其余
参数沿用单通道程序。同一个 m_g 的度规缓存被不同标量 ell 重用。
可选 `--conjugate-ells` 还使用实度规的 h_{-m_g}=h_{m_g}* 关系。
只共轭度规；云场、频率、投影和径向求解均按目标通道独立计算。
直接重构正负 m_g 的回归测试通过，完整主项目测试72 passed。

alpha=.3、rp=20、L_g=4、nr=8、nt=10、h32 的实际运行：

* m_g=-1 的 scalar(2,0) 需880次重构、884.5秒；随后的(4,0)
  重构0次，880次命中缓存，耗时0.851秒。
* m_g=-2 的 scalar(1,-1) 需880次重构、662.0秒；随后的
  (3,-1)、(5,-1)、(3,3)、(5,3) 各重构0次，耗时约0.9秒。
* 共轭路线的 scalar(3,3) 无穷远轨道能流为1.3148099696798758e-5，
  与先前直接正 m_g 的1.31480996904030e-5相对差约4.9e-10。
  两次近视界积分阶数不同，此处仅检验无穷远通量的一致性。

完整参数和每通道计时见两个 `scalar_batch_mg*.json` 报告。
这些是有限分辨率的单半径数据，未达到论文的 L_g=18、全标量求和
与半径扫描要求。批处理性能提升不代表完成数值收敛。

## 并行半径取样与持久缓存

批量入口新增 `--workers N`（默认1保持原行为）。N>1时，用独立进程
同时重构不同半径上的全角节点张量，再供所有标量通道投影使用。
每个完成的半径立即保存到 ignored 的 outputs/metric_cache，后续
同参数重启只补缺失半径。半径网格与单通道程序共用同一构造函数。

缓存标识包含重构模块源码哈希、pybhpt版本、完整度规 provenance、
角节点和精确半径；记录不一致或非有限张量会触发错误。不同半径
计算顺序不影响源文件中的确定性节点顺序。工作进程只做本机数学
计算；预计算耗时和重用/重构半径数记录在批量报告中。

测试比较两进程取样与直接重构、检查共轭、重启后的零重构、返回值
不可修改缓存，以及损坏 provenance 的拒绝。实际全网格性能仍以
完成后的批量报告为准，不能由启动工作进程就宣称已达到加速倍数。

完整测试79 passed。全套运行中独立进程/已有缓存历史的张量最大
相对差曾为5.45e-11，使用1e-9重构对照容差；同一持久缓存重读
仍要求逐值相同。源码标识也覆盖径向方程和角函数依赖，库标识
包含numpy、scipy、mpmath和pybhpt。

共同L_g=6网格的新增实际无穷远通量：scalar(2,2)=1.3412052120e-6，
(4,2)=4.8343176901e-8，(4,4)=3.5204381477e-6。相对于图6数字化
点，分别高约4.97%、5.22%、4.94%。弱通道(6,2)、(6,4)尚有较大的
截断敏感性，不能通过对所有通道乘一个经验系数代替收敛检查。
